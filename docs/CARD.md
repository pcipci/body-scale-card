# Body Scale Card: options and interface

(Options of the card and how it talks to a scale. Build: see the repository README.)

## Dashboard

### Automatic dashboard

The card file also registers a dashboard strategy. Create a new dashboard, open the raw configuration editor and use:

```yaml
strategy:
  type: custom:body-scale-card-dashboard
  language: de       # optional, passed to the cards
  theme: my-theme    # optional, applied to every view
  sort: name         # optional; default: oldest first
  view_icons: initials  # optional: letter icons (first letter of each name) in the header instead of person icons
```

It builds an overview (who weighs next, open measurements, one row per user that opens their view) and one view per user (icon by sex, child icon under 18), and follows when users are added, removed or turn 18. To customise it, use *Take control* in the dashboard menu.

### Dashboard card

Add the card as a dashboard resource (HACS does this for you) and use:

```yaml
type: custom:body-scale-card
```

It finds the scale and its users by itself and shows:

- **the scale as a device** (square, at most 420 px wide): like a real scale its display shows what happened last, with symbols in fixed places and no words (tooltips only). Top: the ten newest readings of all visible people as small numbers 1–10; a tap shows that reading with its date and time (the number gets a frame and fades), a second tap or `history_hold` seconds later (default 30) returns to live. Then the weight on the scale's 0.05 kg raster (`49.05`, from 100 kg one decimal, `00.00` while waiting, `--.--` when idle) with impedance and, beside kg, the change to the reading before; the time a choice or result stays is shown on the lit key (see below), not as numbers; after `display_hold` minutes (default 5) the display goes idle. Values row: BMI (children: percentile) and body fat, each with an arrow (fat only when measured with impedance, otherwise a shoe), and at the right three fixed places: replaced · athlete · fat method 1/2 (or *not stored* for guest and baby/pet). Bottom row: the three modes as symbols (guest, automatic, baby/pet), each above its slim key. Below the scale sit three collapsible entries (they do not repeat per person): the legend of all display symbols and key states, *Chart markings*, and *How the scale works* (bullet points with the scale's symbols and a flow chart of rest, waiting, result and unclear), followed by the *How the scale calculates* section. All texts are German and English. In the value pop-ups percent values also show kilograms, and body fat shows what the other methods would give. Three slim keys under the display (guest, automatic, baby/pet): a tap switches to that mode, pressing the lit one again changes nothing. Three levels: dim = off, dim frame = the mode that is set (automatic when idle), lit = active now (frame and glow, no filled background; a tap on Automatik wakes the display to `00.00` for `display_hold` minutes). No mode is shown while a result or an old reading is displayed; idle shows only the Automatik symbol with a dim frame, no key lit: the chosen or recognised person or mode, also for a reading called up from the history. Any tap on a key ends the result shown and starts from zero; its outline runs back and it fades over the time left (`key_timer_ring`, `key_timer_fade`), and it blinks in the last minute. An unclear reading blinks the suggested keys in turn with the guest key and its symbol (Automatik is off meanwhile): everybody without a reading yet plus the person whose last weight is nearest (all of them when equally near): tapping any person key assigns it, the blinking guest key keeps the reading as a guest's, assigned to nobody and not stored. Only the suggested people get the notification. A choice (person, guest, baby/pet) that runs out switches to active Automatik for the same time, then rest. After a baby/pet result the key of every profile younger than 24 months blinks in turn with the guest key: tapping it stores the weight only (service `assign_baby_result`), the guest key just hides the result. At the bottom edge above the feet one key per user (full names on one line, else two even lines, otherwise initials). Holding a person key fills it with light and after 0.8 s opens that person's view (with `links`). `skin: theme` draws it in the dashboard theme's colours instead of black with a red display,
- the strategy's first view is called **Scale** with a scale symbol and shows the scale without the per-person rows (`list: false`); the per-user weight sensor uses the scale symbol, the BMI percentile a bell curve,
- **own symbols** for body fat (a figure with the belly marked) and BMI (the letters in a frame), registered as `body_scale:body-fat` and `body_scale:bmi` for all of Home Assistant; the body-fat and BMI sensors use them too, so they show in any dashboard,
- **Open measurements** (only those not on the display, so usually hidden), each with time, weight, whether impedance was measured, one button per user (users whose weight matches are highlighted) and **Guest / discard**,
- per user (tabs, with an icon by sex and age): beside the name every rated value as a small coloured symbol (all of them where they fit, otherwise the noteworthy ones and a tick with the number of good ones; a tap opens the value's tile), a line of symbols for sex, age, height (tap to edit), body-fat method (a small scale with 1 = standard, 2 = alternative, a dumbbell for athlete) and private (a crossed-out eye), then one line with the latest weight and the change over 7 and 30 days (calendar symbols), a **graph** with two values on their own axes (weight + body fat, or fat mass + fat-free mass in kg; BMI for adults with the WHO ranges in the background; for children weight + BMI percentile, height and BMI with the percentile curves P3–P97 of the chosen reference in the background) with smooth lines that never overshoot the readings, all ending at the current value (height starts with its percentile), and a subtle dotted grid over 30 days, 1 year or everything. The graph has fixed controls: one pictogram per view; inside the graph's top band each line's colour, name and latest value (plus the reference for percentile curves), and on the right the small grid and curves toggles (remembered per device; greyed out where a view has no curves; in the children's weight + percentile view the WHO / DE buttons show the guide lines P3, P10, P50, P90 and P97 on a 0–100 percentile axis; on every curves toggle the lines glide into the new scale and the curves fade in (not with reduced motion); where the body-fat method changed in the period (from the method sensor's history) the fat, fat-mass and fat-free-mass lines are faded before the switch and a dashed line with a small 1→2 tag marks it; `grid: false` removes the grid; a span of only a few days gets a date per day) (from Home Assistant's long-term statistics, so it reaches back further than the integration's own history), and a **table of measurements**: date, weight with change to the previous reading, BMI, fat, muscle, water, with **move** and **delete** per row.

Every change asks for confirmation first. Options (all optional): `title`, `person` (show only this user, by name or `user_id`), `rows` (rows before "show more", default 10), `pending` / `next_user` / `chart` (`false` hides the section), `hide_empty_pending`, `display_hold` (minutes until the scale display goes idle, default 5), `key_timer` (how the lit key shows the time left: `frame` = thick frame that thins out to the normal one, the default and valid for all keys; `ring` = outline runs back on person keys; `fade` = key darkens; `all`, `none`, or combined like `frame,ring`; the old `key_timer_ring` / `key_timer_fade` set to `true` add ring / fade; blinking in the last minute is the separate option `key_blink`, default off; guest and baby/pet show the time on their display symbol, whose frame blinks in the last minute, Automatic never), `directory` (entity of the user directory; found automatically), `reference` (`who` default or `kh`), `compare_references`, `blink_tolerance_kg` (open reading: besides the suggested people everybody whose last weight lies within this many kg blinks, default 2), `baby_max_months` (age limit for baby/pet persons, default 24), `choice_minutes` (duration of a choice and of the Automatik phase after it; the card hands it to the integration with the service `set_next_user`, otherwise the integration's waiting time applies), `history_hold` (seconds a reading called up from the history stays, default 30; the choice is kept meanwhile), `refresh_seconds` (redraw the card every n seconds, default 0 = off; skipped while a dialog is open), `columns` (any of `weight`, `body_mass_index`, `body_fat_percentage`, `muscle_mass`, `body_water_percentage`, `skeletal_muscle_percentage`, `bone_mass`, `protein_percentage`, `basal_metabolic_rate`, `fat_free_mass`, `visceral_fat`, `subcutaneous_fat_percentage`, `metabolic_age`, `impedance`). `language` (`en` or `de`; default: the Home Assistant profile language), `sort` (`age`, the default: oldest first, or `name`), `grid` (`false` removes the graph grid and its toggle), `curves` (`false` never draws the children's percentile curves; otherwise children's charts have one curves button for the reference chosen in the settings, or, with *Compare both references* switched on there, two buttons, WHO and DE: a tap shows that reference's curves (or guide lines) and draws the percentile line after it, a second tap hides the curves while the line keeps the reference; remembered per view and device, greyed out where a reference has no values for the child's age; adults keep one button for the WHO ranges), `overview` (`true`: who weighs next, open measurements and one row per user with latest weight and 7-day change instead of tabs and graphs; with `links` mapping `user_id` to a view path on the same dashboard, a tap on the row opens that view; the dashboard strategy sets both), `profile` (`false` hides the line with age, height and body fat calculation under the user's name), `info` (`false` hides the **value tiles** under the graph — one per body value with a symbol, the latest value, the change since the reading before and, where a range is established, a coloured rating; a tap opens the explanation with the reference range as a pop-up at the tile, above it where there is room, closed by a tap beside it or Esc — and the collapsible *How the scale calculates* section, which explains how the body-fat methods differ and what standard / alternative / athlete would give for the user's latest reading). Without a `title` the card shows a scale symbol instead of a word, and Guest and Baby/pet are symbol keys (names as tooltips). The labels follow the Home Assistant language (German or English). The former type name `custom:renpho-familie-card` is still accepted, so existing dashboards keep working.

Person devices are named after the Home Assistant language too ("Scale Jane" / "Waage Jane"), as are the *Automatic* / *Guest* options of the next-user select.

## Card interface (two interfaces)

The card knows nothing of a particular scale integration. It reads **S (scale)** from the directory entity (`scale`, `people`, `heights`, `pending`, `pending_candidates`, `guest`, `next`, `next_choices`; flat records, UTC times, `capabilities` as text) and **H (history)** from services with an answer (`get_info`, `get_entries`, `get_series`, `delete_entry`); it loads its entries again when `scale.revision` changes. `set_entry` is the one call that calculates body values; clothes (`clothed`) are an attribute of an entry, with filters for chart and table. Specification (German): `SPEZIFIKATION_Schnittstellen_Waage_Verlauf.md`, formal definition: `interface/`. Option `directory` or `scale`: entity of the directory (found automatically). A separate `history:` source comes with the HTTP adapter.

## Card editor

The card has a visual editor (Edit card): every option is there with a short explanation, grouped as General, Sections, Times, Time on the keys, Scale and recognition, Children. The time shown on a person key is one choice (frame gets thinner, outline runs back, key darkens, none); a combination written in YAML is shown as "Custom" and kept. Values equal to their default are removed from the YAML, options the form does not know (e.g. `links`) are kept. Guest, Automatic and baby/pet never light up their keys: the symbol in the display shows the state, and its frame blinks in the last minute (Automatic never). With `skin: theme` the red symbols of the legends follow the theme's primary colour.

**Where options are stored.** Most options live in the card's own YAML. Six are user-wide and set in the editor's group *For all cards*: `reference`, `compare_references`, `baby_max_months`, `blink_tolerance_kg`, and the consent to load the children's growth tables `growth_who` / `growth_kh` (the tables are separate files with their own licences; without consent the card shows no percentiles or children's curves; the "Enable" button in a child's chart sets the same option). They are stored in Home Assistant's **user data** (`frontend/set_user_data`, key `body_scale_card`), so they apply to all scale cards of that Home Assistant user on all devices; other users have their own. A value written in a card's YAML wins over it. Nothing is stored in the integration. `values_max_age_days` (default 3, 0 = off) lets a value tile show the last reading that has the value, dimmed with its time, when the newest reading lacks it (no impedance).

**Display style.** `invert_modes: true` draws the mode symbols at the bottom of the display inverted (a filled field with a dark symbol: bright when active, dimmed when set and resting; in the last minute the field pulses slowly), `invert_history: true` does the same for the history number at the top. Default off: frames. The legends in the card show which style is on. In the *How the scale calculates* matrix the method in use has a frame around its cell.

`mode_field_width: narrow` (default) or `wide` sets the width of the frame / filled field of the mode symbols: narrow = tight around the symbol, wide = as wide as the key below; both display styles use the same box. `invert_brightness` (20–100, default 65, only with `invert_modes`) is the brightness of the active field in percent of the display colour; the set (resting) field and the pulse phase in the last minute are 40 % of it.
